# Первое испытание МЕТАКОН 5Х3 — 16 ноября 2026

На первом этапе — **только чтение**. Драйвер и сервер проверены имитацией; COM-порты при
подготовке не открывались. Полная [модель и ограничения](metakon-driver.md).

## До подключения

Уточнить и записать модель/версию (513, 523 или 533), наличие интерфейса RS-485,
распайку и полярность адаптера, питание/изоляцию и безопасное состояние установки.
Выбрать фактический COM-порт вручную; закрыть другие программы, использующие эту линию.
Проверить сетевой адрес и существующий канал: номера начинаются с 0.
Уточнить датчик, единицы, положение десятичной точки и коэффициент перевода сырых отсчётов.
Не менять режим регулирования или выходы ради проверки чтения.

[Производитель](https://www.contravt.ru/support/articles/interfeysy-protokoly/protokol-obmena-informatsiey-mezhdu-priborami-tipa-metakon-i-vneshnim-ustroystvom-po-posledovatelnom/)
указывает 8N1 и скорости 2400/4800/9600/19200. 9600 в шаблоне — поддерживаемый вариант,
а не установленный факт для данного прибора. Сверить с его меню.
В шаблоне `timeout_ms = 1000` — запас для первого испытания, не измеренная задержка прибора.

## Запуск в PowerShell

Из корня репозитория создать локальную копию шаблона вне Git и настроить её:

```powershell
Copy-Item examples/metakon-readonly.toml "$env:TEMP/metakon-readonly.local.toml"
notepad "$env:TEMP/metakon-readonly.local.toml"
# Заменить REPLACE_WITH_ACTUAL_COM_PORT, проверить address/channel/baud/scale/unit.
# Оставить write_enabled=false и recording.enabled=false.
cargo run --release -- --config "$env:TEMP/metakon-readonly.local.toml"
```

Сохранить stdout/stderr. Отсутствие ошибки запуска TCP не доказывает доступность прибора:
сервер допускает частичный запуск с недоступным портом. Проверить сообщения об открытии порта.
Коэффициент 1.0 и пустая единица дают сырые integer-отсчёты. Только после сравнения с индикацией
можно задать, например, 0.1 и `degC`, затем перезапустить сервер. Не считать −32768 температурой:
драйвер должен вернуть ошибку датчика.

## TCP: hello, каталог, get и подписка

Во втором PowerShell открыть одно соединение; команда завершается LF:

```powershell
$client = [System.Net.Sockets.TcpClient]::new('127.0.0.1', 7240)
$stream = $client.GetStream()
$stream.ReadTimeout = 15000
$reader = [System.IO.StreamReader]::new($stream)
$writer = [System.IO.StreamWriter]::new($stream)
$writer.NewLine = "`n"
$writer.AutoFlush = $true
$writer.WriteLine('{"id":1,"op":"hello"}')
$reader.ReadLine()
$writer.WriteLine('{"id":2,"op":"describe"}')
$reader.ReadLine()
$writer.WriteLine('{"id":3,"op":"get","key":"metakon1/channel_type"}')
$reader.ReadLine()
$writer.WriteLine('{"id":4,"op":"get","key":"metakon1/measurement"}')
$reader.ReadLine()
$writer.WriteLine('{"id":5,"op":"subscribe","keys":["metakon1/measurement","metakon1/output_power"]}')
1..7 | ForEach-Object { $reader.ReadLine() }
```

Ожидается `hello.version = 1`; в describe — 15 параметров, **все writable=false**,
у measurement/output_power период около секунды. `channel_type` должен быть 3; другое значение
требует выяснения модели, не перехода к записи. Начальный `get` может дать `no_data` до первого опроса;
повторный get должен иметь новый возрастающий ID. Сначала приходит subscribe ACK, затем measurement.
Сопоставить значение с дисплеем и отдельно проверить выходную мощность (%); TCP integer и float различимы.

После подписки ответы и события могут перемежаться. Для завершения подписки:

```powershell
$writer.WriteLine('{"id":6,"op":"unsubscribe","keys":["metakon1/measurement","metakon1/output_power"]}')
do { $line = $reader.ReadLine(); $line; $reply = $line | ConvertFrom-Json } while ($reply.id -ne 6)
$client.Close()
```

Если использовались дополнительные get, увеличить ID unsubscribe соответственно.
В lab-plot использовать глобальные ключи **metakon1/measurement** и **metakon1/output_power**;
конфигурация lab-plot этой работой не менялась. Единицу измерения считать неизвестной до сверки масштаба.

## Ошибки и остановка

Записать естественно возникшие ошибки чтения и точный текст. Не имитировать аварию датчика
на работающей установке. При согласованном безопасном отключении только линии связи ожидать
ошибку/остановку порта, `runtime_unavailable` при последующих обращениях; автоматического
переподключения нет. После проверки подключения требуется явный перезапуск. Не отключать питание
или цепи управления в качестве сетевого теста.
`sensor fault (-32768)` в полном ответе — ошибка наблюдения, опрос других регистров продолжается.
`observation_data_lost` — потеря измерений сервера, а не нормальное закрытие подписки;
сохранить сообщение и журнал, переподключение клиента не восстанавливает потерянные данные.

В серверном окне нажать Ctrl+C, дождаться выхода процесса и освобождения COM/TCP.
SQLite в этом сценарии выключен. Если запись была отдельно разрешена позже,
не завершать процесс принудительно до окончания Recorder shutdown.

Сохранить SHA сервера, TOML без догадок о масштабе, модель/версию и настройки прибора,
тип адаптера, время запуска/остановки, JSON hello/describe/get/событий, stderr,
показания дисплея в те же моменты, частоту/пропуски измерений и все ошибки.
Для анализа кадров использовать только пассивный захват, если он доступен: драйвер не пишет
сырой обмен в лог. Особенно нужны реальные TYP/CRC, положительное/отрицательное измерение,
Boolean false/true при естественном состоянии выходов, отсутствие эха и хвостов.

## Отдельная будущая проверка set — сейчас не выполнять

Только после review результатов чтения и отдельного решения оператора: безопасно изолировать
исполнительные цепи, записать исходное состояние, выбрать один допустимый параметр и значение,
проверить тип/масштаб/шаг, включить `write_enabled=true` в отдельной конфигурации и перезапустить.
Отправить ровно один set с новым ID; сверить ACK, get/readback и индикацию/реальный эффект.
При `outcome_unknown` не повторять set: сначала выяснить фактическое состояние.
Смена значения прибором после ACK возможна и считается несовпадением readback.
Boolean true передаётся как FF по спецификации, варианта с автоматической повторной записью 01 нет.
Возврат исходного состояния — отдельное осознанное действие оператора, не автоматический rollback.
После испытания вернуть `write_enabled=false`. Команды записи в этой инструкции не запускаются.
