# Прямая сериализация Describe

## Побайтовая совместимость

`describe_response()` собирает ссылки на параметры и сортирует их по
`ParameterDescription.id`. Действия сортируются по `ActionDescription.name`.
`serde_json::to_string` сериализует типизированный ответ. Представления
параметров и действий создаются по одному при записи массивов и заимствуют
строки из каталога. Прежние массивы `Value` и корневой JSON-объект устранены.

Порядок объявления полей совпадает с порядком ключей прежнего
`serde_json::Map`. Границы передаются в Serde как `f64`, `i64` или `null`;
ID остаётся `u64`, период опроса — `Option<u128>`. При текущей конфигурации
`serde_json` оба пути используют один форматтер конечных `f64`. JSON по-прежнему
кодирует нечисловые и бесконечные границы как `null`, в том числе для
пользовательских реализаций `CommandBackend`. Экранирование строк также
выполняет Serde.

Тестовый эталон выполняет старый алгоритм и сравнивает строки целиком.
В тестах есть пустой каталог, одиночные и смешанные описания, границы
`f64` и `i64`, отрицательный ноль, `u64::MAX`, периоды выше `u64::MAX`
в наносекундах вплоть до `Duration::MAX`, управляющие символы, Unicode,
сортировка действий и каталог из 128 EMA. Снимки после Configure и Delete
проверяют наследование единиц и исчезновение удалённого сигнала. Отдельные
регрессии сравнивают тела через реальные TCP и WebSocket и проверяют
сохранение очереди при переполнении с учётом TCP LF в бюджете 64 КиБ.
Действующие тесты частичной записи, ID, подписок и аудита проходят вместе
с новыми.

## Фазы

Обе версии измеряют общую фазу `describe` внутри Session. В исходной версии
`describe_sort` состоит из двух замеров, а `describe_json` отдельно считает
две фазы построения дерева. В новой версии одна фаза `describe_sort`
содержит сбор ссылок и обе сортировки. Фаза `describe_json` удалена.
`describe_serialize` теперь включает формирование одного заимствованного
представления за раз и запись JSON. В таблице сериализации исходная
стоимость включает сумму `describe_json` и `describe_serialize`, а новая —
`describe_serialize`. Внутренние фазы входят в `describe`, поэтому
показатели не складываются с временем удержания.

## Методика

База — `7112a8cebb85808f2fe25535b849b4954e228edc`. Код нового сериализатора —
`ecf8ffcf3d3e835a88daf693550ce753ca5e6977`. Оба бинарника собраны с
`--release --locked --features gate-metrics` в отдельных подкаталогах
`CARGO_TARGET_DIR` из README. В отдельную рабочую копию базы скопированы
два файла стенда из этой ветки. Их SHA-256 совпадают
между рабочими копиями. Код библиотеки в копии базы соответствует
указанному базовому SHA.

- 19 ноября 2026. Windows 10 Pro 22H2, сборка 19045, AMD Ryzen 5 6600H (6 ядер,
  12 логических процессоров), rustc 1.95.0 (59807616e),
  `x86_64-pc-windows-msvc`. Используется профиль Cargo Release проекта.
- Пять пар отдельных запусков. В нечётных парах первой шла исходная
  версия, в чётных — новая. Графы — цепочки из 8, 32 и 128 EMA.
- Каждый сценарий создаёт свежий `DeviceService`, подаёт начальный образец,
  делает 8 прогревочных раундов и сбрасывает статистику `gate`. Замер
  включает 256 раундов прямых запросов на клиента или 48 запросов по
  loopback. При конкуренции клиенты и поток измерений стартуют каждый
  раунд через `Barrier`. Смешанная нагрузка использует три клиента,
  по одному для Ping, производного Get и Describe, с одним
  параллельным образцом на раунд.
- Базовый и новый бинарники проверяют ID, статус, содержимое ответов,
  отсутствие лишних ответов прямого Session и актуальность последнего
  вычисленного значения. Дополнительно для каждого Describe, включая
  смешанный сценарий, стенд считает размер UTF-8 и хеш всего тела.
  Сумма хешей по ответам сохраняет кратность и устойчива к порядку
  завершения клиентов. Хеширование идёт после обработки запроса, вне
  `gate`. Побайтовым эталоном служит отдельный регрессионный тест.
- В TCP `gate` измеряется на уровне `tcp_drive`, включая оборот работы
  с сокетом и возможный дополнительный оборот. В WebSocket измеряется
  `receive_message`. Клиентский RTT считается от отправки до получения
  целого ответа на loopback до его проверки. Он включает работу ОС,
  цикл сокета и штатные паузы сервера.
- В таблицах приведены медианы пяти значений каждого показателя в каждой
  версии. Парный выигрыш — медиана `(до − после) / до` по парам.
  В скобках указано число пар со строго положительным выигрышем.
  Основной показатель — полное удержание `gate`. Перцентили фаз и `gate`
  выражены верхними границами интервалов логарифмических гистограмм из
  блока 5, поэтому близкие значения могут дать одинаковый перцентиль.

Из корня рабочей ветки можно подготовить обе сборки следующими командами.
Путь `$base` должен быть свободен.

```powershell
$base = 'D:\rust_projects\lab-server-describe-base'
$target = 'D:\rust_projects\lab-server-agent-build'
git worktree add --detach $base 7112a8cebb85808f2fe25535b849b4954e228edc
Copy-Item examples/service_gate_bench.rs "$base/examples/service_gate_bench.rs"
Copy-Item examples/service_gate_bench/session_requests.rs "$base/examples/service_gate_bench/session_requests.rs"
$env:CARGO_TARGET_DIR = "$target/describe-before"
cargo build --manifest-path "$base/Cargo.toml" --release --locked --features gate-metrics --example service_gate_bench
$env:CARGO_TARGET_DIR = "$target/describe-after"
cargo build --release --locked --features gate-metrics --example service_gate_bench
```

Пять пар запускаются бинарниками из подготовленных каталогов сборки.

```powershell
$before = 'D:\rust_projects\lab-server-agent-build\describe-before\release\examples\service_gate_bench.exe'
$after = 'D:\rust_projects\lab-server-agent-build\describe-after\release\examples\service_gate_bench.exe'
foreach ($pair in 1..5) {
    $order = if ($pair % 2 -eq 1) { @($before, $after) } else { @($after, $before) }
    foreach ($executable in $order) {
        $version = if ($executable -eq $before) { 'before' } else { 'after' }
        & $executable --describe-comparison $pair > "$version-$pair.csv"
        if ($LASTEXITCODE -ne 0) { throw "$version pair $pair failed" }
    }
}
```

В CSV записаны все повторы. Столбцы `version` и `paired_position`
фиксируют версию и порядок, `repeat` содержит номер пары. Строки
`describe_payload` содержат число ответов, длины и хеш их тел. Размер TCP
записан в байтах тела без LF. [Сырые измерения](describe-serialization-performance.csv)

## Ограничения

Измерения выполнены на одном компьютере с активным `gate-metrics`.
Стоимость инструментирования входит в наблюдение, причём у новой
реализации меньше внутренних фаз. Размеры графа внутри прогона шли
по возрастанию, а порядок версий чередовался. Из-за разброса частот и
планирования абсолютные значения между размерами могут быть
немонотонными. Для вывода об ускорении сравниваются одинаковые
сценарии внутри пар.

Нагрузка использует цепочки EMA, имитационные устройства и loopback
с одним последовательным сетевым клиентом на сценарий. Представление
реальной сети, нагрузки физических портов и других топологий требует
отдельного измерения. Каталог по-прежнему строится при каждом Describe.
Повторная проверка каталога для производного Get также остаётся
отдельной статьёй затрат.
