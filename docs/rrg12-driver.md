# Элточприбор РРГ-12

`driver = "rrg12"` публикует семь параметров для чтения по Modbus RTU. По умолчанию раз в секунду
опрашивается `flow_percent`. Другие параметры читаются по запросу или по расписанию
`devices.poll_periods_ms`.

## Карта и обмен

Все смещения нулевые. Каждое чтение драйвера отправляет один адресный запрос `03h` на одно слово
big-endian. CRC-16/MODBUS передаётся младшим байтом вперёд.

| Смещение | Параметр | Кодировка и результат | Команды по руководству |
| --- | --- | --- | --- |
| `0000h` | `network_address` | Младший байт слова, целое | 03h, 06h |
| `0001h` | `serial_number` | Беззнаковое слово, целое | 03h |
| `0002h` | `status_flags_1` | Слово битов, возвращается целиком | 03h, 06h, 0Fh для отдельных флагов |
| `0003h` | `status_flags_2` | Слово битов, возвращается целиком | 03h |
| `0004h` | `setpoint_percent` | Беззнаковое слово / 100, % | 03h, 06h |
| `0005h` | `flow_percent` | Бит 15 задаёт знак, биты 0–14 — модуль в сотых долях %, документированный диапазон −0,5…130 % | 03h |
| `0006h` | `baud_code` | Сырое беззнаковое слово. В §6.1.4 указаны 0 для 9600, 1 для 38400 и `2-FFh` для 19200 | 03h, 06h |

| Свойство | Данные источника и пределы драйвера |
| --- | --- |
| Функции | 03h — чтение группы регистров, 06h — запись слова, 0Fh — запись группы флагов. Драйвер использует 03h. |
| Измерение со знаком | В §3 приведено соответствие `83E8h` → −1000, в §7.2 `8004h` → −4. Пример §7.2 проверяется как проводной вектор с CRC. |
| Адрес прибора | §6.1.5 указывает 1–255. Драйвер принимает стандартный диапазон RTU 1–247. Адрес 0 и расширение 248–255 исключены. Пример с адресом 0 в §7.1 противоречит оговорке о broadcast в §6.1.5. |
| Линия | RS-485, 8N1, 9600/19200/38400 бод. Руководство указывает заводские 19200. Параметры действующего порта задаются в `[[ports]]`. |
| Границы кадра | Не более 256 байт, непрерывная передача. Руководство указывает тишину 20 мс. Драйвер выдерживает её перед отправкой и после полного ответа, включая exception. |
| Exception | Адрес, функция с установленным битом 7, однобайтовый код, CRC. §5.4 перечисляет 01, 02, 03, 04. Для РРГ-12 код 04 означает недопустимое количество регистров или флагов. Библиотека сохраняет числовой код. |

Фрагмент конфигурации устройства. `rs485` должен совпадать с ID заранее настроенного
`[[ports]]`, `3` — пример адреса.

```toml
[[devices]]
id = "rrg"
driver = "rrg12"
port = "rs485"

[devices.options]
address = 3
write_enabled = false
```

`write_enabled` по умолчанию `false`. Значение `true` отклоняется при загрузке.
Каталог и прямые вызовы `Driver::write` доступны только для чтения. Для `flow_percent`
нужно подтвердить режим РРГ: по §6.1 тот же регистр в режиме РДГ содержит процент давления.
Пересчёт в л/ч требует паспортной полной шкалы и данных о газе. На отдельном стенде предстоит
сверить ревизию, настройки линии и адрес, знаковое измерение, диапазон, битовые поля, коды ошибок
и время ответа. Для реализации управления нужно отдельно уточнить правила конкретной ревизии,
включая режим восстановления питания и приоритет внешнего управления. У §6.2 и его примечания
расходится трактовка бита восстановления, а у §7.5 текст расходится с примером кадра.

## Rust API `driver::modbus_rtu`

| API | Назначение |
| --- | --- |
| `crc16(bytes) -> u16` | CRC-16/MODBUS. На линию передаётся `to_le_bytes()`. |
| `interframe_silence(baud, data_bits, parity_bit, stop_bits)` | t3.5 по формату физического порта. При скорости выше 19200 возвращает 1,75 мс. |
| `ReadRegisters::new(slave, table, start, count)` | Проверка адреса и диапазона (1–125 слов). `RegisterTable::Holding` — 03h, `RegisterTable::Input` — 04h. |
| `request.encode()` / `request.decode(frame)` | Формирует запрос / проверяет один полный ответ и возвращает `Vec<u16>`. |
| `request.exchange(io, silence)` | Один запрос через существующий `DeviceIo`. Передаётся максимум между t3.5 и паузой из паспорта устройства. |

Пример для будущего прибора с одним стандартным регистром FC04. Смещение берётся из спецификации
этого прибора. Знаковость, масштаб, порядок слов составных величин и права записи задаёт его драйвер.

```rust
use lab_server::driver::{DeviceIo, DriverError};
use lab_server::driver::modbus_rtu::{ReadRegisters, RegisterTable, interframe_silence};

fn read_raw(
    io: &mut dyn DeviceIo,
    address: u8,
    offset: u16,
    baud: u32,
) -> Result<u16, DriverError> {
    let silence = interframe_silence(baud, 8, true, 1)?; // Для порта 8E1.
    let request = ReadRegisters::new(address, RegisterTable::Input, offset, 1)?;
    Ok(request.exchange(io, silence)?[0])
}
```

Внутри модуля транспорт берёт ожидаемую длину нормального ответа от реализации функции,
выделяет пятибайтовый exception и проверяет общие поля. Новые функции могут добавлять свои
кодеки, используя тот же обмен. Подтверждённый exception завершает транзакцию. Несовпадение
адреса, функции, длины, CRC, таймаут или уже буферизованный хвост означают десинхронизацию.
EOF и ошибки отключения означают потерю соединения. В двух последних случаях PortWorker
останавливает весь порт. Повторной отправки нет.

`DeviceIo` отдаёт порции байтов вместе с задержками ОС и USB. Строгий контроль физической
паузы t1.5 внутри ответа и обнаружение хвоста, который ещё не попал в прочитанную порцию,
требуют стендового контроля на линии. [Анализ общей RS-485](erstevak-driver.md#совместная-rs-485)
