# Erstevak MTM9D-KF25

`driver = "erstevak"` публикует один параметр `pressure` в mbar. Это предварительная
реализация формата Thyracont V1. Поддержку адресного V1 на конкретной аппаратной ревизии и
прошивке MTM9D-KF25 предстоит подтвердить.

## Источники

- Спецификация V1 от 03.08.2020 определяет кадр, чтение `M`, контрольную сумму,
  ошибки и тайминги. В перечне моделей V1 нет обозначения MTM9D. [Thyracont V1](https://thyracont-vacuum.com/download/243826)
- Спецификация V2.1.10 описывает другой протокол. В разделе Streaming Mode отдельно приведён
  формат измерения V1, включая код ошибки `1`. [Thyracont V2](https://thyracont-vacuum.com/download/243369)
- В Scietex класс `ErstevakRS485V1Gauge` наследует клиент Thyracont V1. Проверены
  `request_gauge`, запрос `M`, проверка checksum и адреса, разбор мантиссы и экспоненты.
  В том же репозитории есть транспорт V2, в коде которого MTM9D также приведён как пример.
  Модель `MTM9DGauge` из `erstevak/analog.py` относится к аналоговому выходу.
  [Код Scietex, зафиксированная ревизия](https://github.com/bond-anton/scietex.hal.vacuum_gauge/tree/9a24a96f80a4be5a169c5ab099d0d090a702e7ed/src/scietex/hal/vacuum_gauge)
- Производитель указывает интерфейс RS-485 и диапазон скоростей семейства. Сервисный материал
  для MTM9D описывает цифровые статусы `000000`, `1`, `5` и `7`. Для `5` и `7` полный
  адресный кадр V1 пока не подтверждён. [Erstevak MTM9D](https://erstvak.com/brands/shirokodiapazonnye-vakuummetry-erstevak/erstevak-seriya-mtm9d/) ·
  [Диагностика MTM9D](https://tula-term.ru/servis-i-podderzhka/chasto-zadavaemye-voprosy/vakuummetry/mtm9d-vozmozhnye-neispravnosti-i-metody-ustraneniy)

## Адресный обмен V1

| Поле или операция | Формат и ограничение |
| --- | --- |
| Адрес | Три десятичные ASCII-цифры `001`…`999`, в TOML целое 1…999 |
| Давление | Запрос `ADR M CKS CR`, ответ `ADR M DDDDEE CKS CR`. Разделителей в кадре нет. |
| Значение | `DDDD / 1000 × 10^(EE−20)` mbar. Мантисса без ведущего нуля. Пример спецификации `001M982122V\r` → 982,1 mbar. |
| Контрольная сумма | Сумма байтов адреса, кода и данных по модулю 64 плюс 64. Передаётся одним ASCII-байтом. |
| Граница | Один `CR` (`0x0D`). Запрос давления занимает 6 байт, нормальный ответ 12 байт. |
| Выход из диапазона | `M000000` / `M999999` — ниже / выше диапазона. Публикуются как ошибки наблюдения. |
| Ошибки | V1 определяет `NO_DEF`, `X_RANGE` и `X_LOGIC`. Для запроса давления распознаются `NO_DEF`, `M_RANGE` и `M_LOGIC`. Также распознаётся `M1` по описанию полезной нагрузки V1 в документе V2. |
| Линия | Документ V1 задаёт 9600 бод, 8 бит, без чётности, 1 стоп-бит. Эти настройки описывают V1 и требуют проверки на MTM9D данной ревизии. |
| Время | Документ V1 указывает период дискретизации 100 мс и интервал до ответа до 10 мс. Таймаут физического порта задаёт `ports.timeout_ms`, включая время передачи и задержки драйвера ОС. |
| Другие команды | В спецификации есть идентификация `T`, логирование и настройки. В рабочем драйвере используется только запрос `M`. |

```toml
[[devices]]
id = "vac"
driver = "erstevak"
port = "rs485"

[devices.options]
address = 1
```

`rs485` должен совпадать с ID физического порта. Адрес в примере требуется сверить с прибором.
По умолчанию опрос выполняется раз в секунду. Драйвер посылает один запрос на чтение.
Калибровка, настройки реле, запись адреса и управление listening/streaming mode отсутствуют.
Для опроса требуется ревизия, отвечающая на `M` адресным кадром. При стендовой проверке
нужно подтвердить версию протокола, UART, интервалы и формат ответов при нормальном давлении и
ошибках. Давление следует сверить с независимым показанием.

Полный ответ с правильным адресом, checksum и распознанным статусом завершает транзакцию
даже при ошибке прибора. Перед возвратом полного ответа выдерживается пауза 9 мс для общего
порта с МЕТАКОН. Таймаут, неверный адрес, повреждённый кадр или хвост в буфере останавливают
PortWorker с `Desynchronized`. EOF и ошибки отключения останавливают его с `Disconnected`.
Повторной отправки нет. Границы метаданных `pressure` описывают представимые числа V1.
Метрологический диапазон серии по карточке производителя — 5×10⁻⁹…1000 mbar.

## Совместная RS-485

В имитации один PortWorker последовательно обслуживает три МЕТАКОН 5Х3, РРГ-12, Erstevak
и дополнительное логическое Modbus-устройство на другом адресе. Проверены независимые
адреса, переключения между тремя форматами, фрагментация ответов и интервалы на хосте.
Все приборы на физической линии используют общий baud, parity, data bits и stop bits.
9600/8N1 — пересечение документированных настроек МЕТАКОН, РРГ-12 и V1. Для РРГ-12
руководство указывает заводские 19200 и возможность возврата к 19200 при старте в аналоговом
режиме. Фактические настройки всех пяти приборов, выводы адаптера и электрическую
совместимость нужно проверять на стенде. [МЕТАКОН](metakon-driver.md) · [РРГ-12](rrg12-driver.md)

| Приёмник и чужие кадры | Что следует из опубликованных форматов |
| --- | --- |
| МЕТАКОН ← РРГ-12 | В выровненном запросе FC03 второй байт равен 3, а каналы 5Х3 занимают 0–2. Пятибайтовая длина чтения МЕТАКОН отличается от восьмибайтового запроса RTU. |
| МЕТАКОН ← V1 | Второй ASCII-байт адреса лежит в `0x30`…`0x39`, за пределами каналов. Байт `M` в позиции команды МЕТАКОН лежит вне диапазона 0/1. |
| РРГ-12 ← МЕТАКОН | В выровненном кадре канал 0–2 попадает в поле функции RTU. Ни одна из этих функций не входит в набор РРГ-12. Перебор 256 адресов, трёх каналов и пятнадцати регистров чтения 5Х3 нашёл четыре кадра с корректным CRC-16 RTU. Все четыре имеют код 02h и длину 5 байт, тогда как стандартный запрос 02h требует 8 байт. Документ РРГ допускает exception для неподдерживаемой функции. Порядок проверок прошивки требует проверки. |
| РРГ-12 ← V1 | Десятичные ASCII-байты могут численно совпасть с адресом RTU. Второй байт попадает вне функций РРГ-12. Ни один из 999 полных запросов `M` не прошёл проверку CRC-16 RTU в программном переборе. |
| V1 ← МЕТАКОН или РРГ-12 | Выровненные кадры чтения имеют второй байт меньше `0x30`, поэтому не образуют трёхзначный ASCII-адрес. Двоичные кадры могут содержать `CR` внутри. Поведение при поиске следующей границы зависит от прошивки. |

Эти проверки относятся к кадрам с известными границами. Хвосты, эхо адаптера, смещение
границы, CRC-коллизии, несовпадающие тайминги и внеочередные ответы могут привести к
ложному распознаванию или одновременной передаче двух ведомых. У RTU пауза 20 мс нужна
самому РРГ-12. Драйвер выдерживает её на своих транзакциях. Последовательные транзакции
других драйверов могут объединяться в приёмном буфере РРГ-12, пока между ними меньше 20 мс.
USB и ОС могут доставлять байты пачками, поэтому программные интервалы хоста не измеряют
границы на проводе. До совместного включения предстоит отдельно проверить отсутствие
ответов и изменений состояния на чужих кадрах в обоих направлениях, время удержания
передатчика, согласование линии, смещение и полярность A/B. Физическая совместимость
пяти устройств пока не установлена.
