# МЕТАКОН 5Х3: драйвер и границы проверки

[Запуск](../README.md) · [Первое испытание](metakon-hardware-test.md) · [Шаблон TOML](../examples/metakon-readonly.toml)

Реализация для регистровой модели МЕТАКОН 513/523/533 (код канала `0x03`).
Это бинарный протокол МЕТАКОН, не Modbus. Физическое оборудование при разработке не открывалось.

## Конфигурация

В `DeviceConfig.options` принимаются только следующие поля:

| Поле | Тип, ограничения и назначение |
| --- | --- |
| `address` | Обязательное целое 0–255, сетевой адрес |
| `channel` | Обязательное целое 0–2; 513 имеет канал 0, 523 — 0–1, 533 — 0–2 |
| `process_value_scale` | Обязательное положительное конечное число; произведение на 9999 должно быть конечным |
| `process_value_unit` | Необязательная строка, по умолчанию пустая; не более 64 байт, без управляющих символов |
| `write_enabled` | Boolean, по умолчанию `false` |

`create_driver` проверяет настройки всех устройств до открытия оборудования. Номер COM, скорость,
таймаут и остальные параметры линии остаются в `[[ports]]`. Драйвер не открывает порт,
не создаёт потоков и не меняет общий планировщик. Совместимые устройства с разными адресами/каналами
могут пользоваться одним PortWorker. Модель и фактическое наличие выбранного канала оператор
проверяет до испытания; дополнительного скрытого чтения идентификатора перед каждой командой нет.

Масштаб не выбирается по предполагаемому датчику. Например, подтверждённые десятые доли градуса
задаются `process_value_scale = 0.1`, `process_value_unit = "degC"`. Коэффициент 1.0 в шаблоне
означает сырые целые отсчёты с неизвестной единицей, а не подтверждённую температуру.

## Каталог регистров

В таблице даны диапазоны **сырых регистров**. Звёздочка означает умножение значения и границ
на `process_value_scale`, единица берётся из `process_value_unit`.
При коэффициенте 1 эти параметры — integer, при другом коэффициенте — float.
Остальные числовые параметры всегда integer; Boolean не преобразуется в число.

| Адрес | Локальный ключ | Тип на линии | Диапазон / единица | Доступ прибора |
| --- | --- | --- | --- | --- |
| 00 | `channel_type` | Ubyte | 0…255, ожидается 3 | R |
| 01 | `measurement` | Int | −999…9999 * | R |
| 02 | `setpoint` | Int | −999…9999 * | RW |
| 03 | `proportional_band` | Uint | 1…9999 * | RW |
| 04 | `integral_time` | Uint | 1…30000 s | RW |
| 05 | `derivative_time` | Ubyte | 0…255 s | RW |
| 06 | `output_power` | Byte | −100…100 % | RW |
| 07 | `pwm_positive` | Bool | false / true, пустая единица | R |
| 08 | `pwm_negative` | Bool | false / true, пустая единица | R |
| 09 | `upper_setpoint` | Int | −999…9999 * | RW |
| 0A | `upper_hysteresis` | Ubyte | 0…255 * | RW |
| 0B | `upper_output` | Bool | false / true, пустая единица | RW |
| 0C | `lower_setpoint` | Int | −999…9999 * | RW |
| 0D | `lower_hysteresis` | Ubyte | 0…255 * | RW |
| 0E | `lower_output` | Bool | false / true, пустая единица | RW |

При `write_enabled = false` **все** параметры объявляются read-only, и прямой `Driver::write`
отказывает до I/O. Разрешение записи не делает регистры R записываемыми.
По умолчанию опрашиваются только `measurement` и `output_power`, раз в секунду каждый;
переопределения через `devices.poll_periods_ms` работают как у других драйверов.
Чтение одного регистра не публикует наблюдений других регистров. `get` опрашиваемого параметра
читает общий кеш; `get` остальных выполняет транзакцию. Ключи включают ID устройства, например
`metakon1/measurement`. TCP/WS v1, парсер и SQLite не изменены.

## Транзакции

Порядок байтов — little-endian. CRC-8: начальное FF, отражённый полином 8C, без финального XOR.
Поддерживаются пять типов этой модели: Bool, Ubyte, Byte, Uint, Int.
Широкие типы общего протокола (строки, float32/64, 32-битные целые) модель 5Х3 не использует.

| Обмен | Структура | Размер |
| --- | --- | --- |
| Запрос чтения | DEV CHA REG 00 CRC | 5 |
| Ответ чтения | DEV CHA REG 00 TYP DATA CRC | 7 или 8 |
| Запрос записи | DEV CHA REG 01 TYP DATA CRC | 7 или 8 |
| Подтверждение записи | DEV CHA REG 01 CRC | 5 |

Проверяются длина, CRC, адрес, канал, регистр, команда, тип и биты доступа.
Биты доступа в ответе — физические права регистра; программный read-only их не меняет.
Boolean кодируется и принимается только как `00` / `FF`.
Куски одного кадра дочитываются без повторной отправки запроса. Уже буферизованный лишний
хвост отвергается. Неполный ответ/таймаут, неправильный CRC или заголовок означают
`Desynchronized`; EOF и ошибки отключения — `Disconnected`. В обоих случаях существующий
PortWorker останавливает общий физический порт: следующая команда не читает оставшийся хвост.
Автоматического переподключения, очистки буфера с продолжением или повтора транзакции нет.

`Synchronized` используется для отказа до I/O или семантической ошибки полностью проверенного
ответа: `measurement = -32768` — неисправность измерения, выход за диапазон — ошибка регистра.
Такая ошибка публикуется как ошибка наблюдения; соседние чтения и управление продолжаются.
Значение −32768 не масштабируется и не попадает в график как температура.

Запись: проверка разрешения, точного типа и диапазона → **одна WR** → проверка ACK →
**одно чтение того же регистра** → сравнение сырых значений. Масштабированный set должен
попадать в целый шаг регистра; допускается лишь погрешность представления float, не округление
до другого значения. Автономное изменение выхода прибором тоже может дать несовпадение readback.
Потеря ACK, ошибка readback или несовпадение не дают успешного ответа и никогда не вызывают
повторную WR. Полный корректный readback с другим значением сохраняет синхронизацию порта.
По действующему контракту PortWorker любая ошибка после начала Set превращается в
`outcome_unknown`; это относится и к локальному отклонению нецелого шага после `try_start`.
До `try_start` таймаут отменяет запись, после — результат неопределён; позднего второго ответа нет.

Ограничение исходного протокола: в нём нет ID транзакции. Драйвер исходит из обмена команда–ответ
без самопроизвольных кадров. Общий `DeviceIo` не предоставляет проверки межкадровой тишины
или неблокирующего просмотра ещё не пришедших байтов. Лишний уже доступный байт обнаруживается;
произвольно поздний дубликат полностью корректного ответа на тот же регистр отличить невозможно.
После любого обнаруженного нарушения границы работа порта прекращается. Реальную пакетизацию,
эхо адаптера и отсутствие поздних дублей нужно проверить на стенде, не маскируя их повтором.

## Проверено без оборудования

- Unit-тесты: независимые CRC/кадры, пять типов, все 15 адресов и диапазонов, флаги/CRC/длины,
  фрагменты, EOF/таймауты, sentinel, масштаб, read-only, ACK/readback и отсутствие повторов.
- Интеграция: фабрика до открытия портов, настоящие PortWorker/DeviceService/TCP,
  hello v1, каталог, get, subscribe ACK/измерения/ошибки, unsubscribe и shutdown.
- Общий порт: разные адреса и каналы, последовательные транзакции, отказ очереди после
  повреждённого ответа; успешный опрос и ошибка датчика не порождают наблюдений другого регистра.
- Set: таймаут до начала и после начала с управляемым каналом, потеря ACK, отключение,
  повреждение ACK, отказ/несовпадение readback; ровно одна WR, отсутствие ложного/повторного ACK.

Эмулятор не подтверждает электрическое подключение, текущие настройки прибора, отображаемый
масштаб, реальные задержки, содержимое флагов TYP и поведение выходов/энергонезависимой памяти.
Первое физическое испытание — только чтение, по отдельной инструкции.
